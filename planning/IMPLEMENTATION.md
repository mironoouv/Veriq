# Технический план Veriq v1.0

Основание — `VERIQ_SPEC` §1–3, `ARCHITECTURE`, `SECURITY`, `DATABASE`, `API_CONTRACTS`, ADR-001–016 и `ROADMAP`. Все 16 ADR фиксируют утверждённые продуктовые решения. OQ-01–14 остаются открытыми.

## Риски и решения, требующие согласования

|---|---|---|

Пока попытка активна, устройство не устанавливает обновления. Срочное обслуживание требует явного завершения экзамена или предусмотренного переноса с аудитом. |

Предложения выше требуют решения владельца. Для Foundation можно использовать публичные системные health-пробы без доступа к пользовательским или tenant-ресурсам. Redis предусмотрен для временного состояния и очередей. PostgreSQL остаётся источником данных.

## Foundation 1a

Выбран минимальный путь браузер → Vite proxy → FastAPI → PostgreSQL. API проверяет БД через SQLAlchemy, а запуск контейнера API зависит от успешной миграции Alembic. Первая ревизия создаёт организации и глобальных пользователей без заполнения. Доступ к этим таблицам появится после серверных правил авторизации. Базовый workflow CI запускает проверки и проверку Compose. Сканирование секретов и браузерные сценарии остаются частью 1d.

Python 3.11 соответствует установленному Windows-интерпретатору и разрешённым зависимостям `uv.lock`. Node 24 совместим с Vite 8, Vue I18n и Tailwind 4. Прямые и транзитивные зависимости фиксируются lock-файлами. Базовые образы закреплены тегами релизов для dev; проверка образов и фиксация digest для продакшна входят в 1d.

Vue I18n 11.4.18 ссылается в декларациях на тип, отсутствующий в Vue 3.5.45.
Для внешних файлов деклараций включён `skipLibCheck`. `vue-tsc` продолжает
проверять исходники проекта в строгом режиме. Убрать обход после устранения
несовместимости в зависимостях.

Источники совместимости: [Vite 8](https://v8.vite.dev/blog/announcing-vite8), [uv lock/sync](https://docs.astral.sh/uv/concepts/projects/sync/), [Compose depends_on](https://docs.docker.com/reference/compose-file/services/).
