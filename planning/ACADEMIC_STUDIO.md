# Этап 3 — Academic & Studio

**Статус: PROPOSED.** Реализация начинается после архитектурного ревью.

## Порядок и границы

[ROADMAP](ROADMAP.md) и [IMPLEMENTATION](IMPLEMENTATION.md) ставят Academic & Studio перед Exam Engine. [ТЗ](../docs/VERIQ_SPEC.md) требует учебные группы, дисциплины, преподавателей, участников, архивирование и переводы. [DATABASE](../docs/DATABASE.md) уже задаёт соответствующие имена. [ARCHITECTURE](../docs/ARCHITECTURE.md), [API_CONTRACTS](../docs/API_CONTRACTS.md), ADR-003, ADR-005 и ADR-006 остаются основанием для изоляции, банков и назначений.

Переиспользуем organizations, users, organization_memberships, роли, grant_epoch, Sessions и tenant-контекст. Курсы/дисциплины — courses, учебные классы/группы — study_groups. Участие студента в группе — group_memberships, связь преподавателя с дисциплиной — course_teachers. Принадлежность к курсу или группе сама по себе не назначает роль и не подтверждает членство. Курсы и группы предлагается хранить как независимые сущности организации. Связь курса с группой нужна только при подтверждённом сценарии ведения конкретного потока. Учебное назначение преподавателя и экзаменационное assignment — разные операции в существующей модели.

Первые два PR дают минимальный контекст Studio. Код класса из ADR-003 остаётся привязанным к реальной группе, с отдельной приёмкой. До согласования контракта его нельзя использовать для автоматического предоставления членства или роли. Attempt, оценивание, Judge и Agent относятся к последующим этапам.

## Общие требования к безопасности и проверкам

- Использовать проверенную tenant-сессию, текущий grant_epoch, явное разрешение RBAC и ABAC для конкретного ресурса. Проверять владение, назначение и ACL по операции. Superadmin без отдельного основания не получает данные организации. Полномочия Vue отражают ответ API, проверку выполняет сервер.
- Tenant-scoped таблицы защищать ENABLE/FORCE RLS. Составные FK включают organization_id и запрещают ссылки между tenant. Применять SELECT, INSERT, UPDATE и DELETE-политики с WITH CHECK там, где нужна запись. Runtime не получает ownership или BYPASSRLS. Контекст живёт в транзакции и сбрасывается после COMMIT/ROLLBACK. Любая новая SECURITY DEFINER функция требует отдельного обоснования и проверки EXECUTE.
- Для каждого PR проверить TEN-01 под ограниченными DB-ролями: A/B, подмена идентификаторов и ссылок, чтение и DML, отсутствие контекста, повторное соединение, отзыв роли и членства. Для мутаций проверить идемпотентность, конкуренцию и безопасный аудит. Для Vue проверить отказ доступа, повтор и конфликт, клавиатурный сценарий и отсутствие данных старого tenant после переключения.
- API типизируется в OpenAPI, изменяющие операции используют существующие CSRF/Origin и согласованные Idempotency-Key или expected_revision. Новые маршруты проверяются на тестовом HTTPS. Публичный Auth остаётся NOT READY.

## Открытые решения

1. Нужна ли связь курса с группой уже на этапе 3 и может ли одна группа проходить несколько курсов. Предложение — начать без связи и добавить её по утверждённому сценарию, без дублирования учебной группы.
2. Разрешено ли несколько одновременных членств студента в разных группах и в какой области перевод должен быть исключительным. Предложение — запретить пересечение интервалов только для одной пары группа/участник до утверждения более строгой политики.
3. Кто кроме Org Admin управляет составом и как ограничивать видимость списков для Teacher, Student, Proctor и Technician. Предложение — явные разрешения и ABAC по назначению, с закрытым доступом по умолчанию.
4. Когда подключать групповые коды, кто их модерирует и как мигрировать существующие коды организации. Предложение — отдельный срез после PR 2 с реальным group FK и явным допуском.
5. Политика архивирования и исторических ссылок, область групповой цели на момент назначения, состав группы на момент старта и поведение перевода при открытом окне. Правила должны быть согласованы до PR 6.
6. Очерёдность типов вопросов, политика ключей ответов, права use/edit и подтверждение полного набора восьми настроек с передачей гарантий в Exam Engine. Согласовать до PR 4–5.
