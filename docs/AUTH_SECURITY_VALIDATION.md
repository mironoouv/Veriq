# Auth Slice 9 — Security Validation Report

**Решение для публичного Auth — NOT READY.** Проверено тестовое HTTPS-окружение с синтетическими аккаунтами, PostgreSQL, Redis и локальным mailbox. Production Compose проверялся с выключенными тестовыми маршрутами. Активация публичного Auth требует отдельного решения.

Основания — AUTH-01–03, TEN-01, ADR-003, ADR-014, ADR-015 и раздел 9 AUTH_ACCOUNT_SECURITY. Новых миграций и механизмов авторизации нет.

## Матрица сценариев

| Проверка | Уровень и результат |
|---|---|
| Регистрация, письмо и подтверждение | Windows HTTPS Chromium прошёл: GET ссылки не подтверждает адрес, POST подтверждает, повтор proof отклонён. До подтверждения вход закрыт. |
| Вход, cookies и tenant switch | Chromium прошёл: верный/неверный пароль, Secure/HttpOnly/SameSite=Lax, запрет чужого tenant, переход в организацию с обязательной MFA отклонён для сессии без фактора. |
| TOTP, резервный код, step-up | Chromium прошёл: операторский enrollment, challenge без сессии, TOTP и recovery code replay, MFA rate limit, step-up и последующее управление приёмом. Правила Superadmin и Technician проверяются дополнительно в PostgreSQL-интеграции. |
| Фиксация, ротация и отзыв | Chromium прошёл: подставленный токен не становится сессией, старый токен после ротации отвергнут, logout и revoke-all. Гонки отзыва и смены полномочий покрывает PostgreSQL. |
| Смена пароля и reset | Chromium прошёл: другая сессия недействительна после смены пароля, reset через mailbox одноразовый, привилегированный вход после reset снова требует MFA. |
| Независимое MFA recovery | Chromium прошёл: заявка создана, самоодобрение отклонено. Полная цепочка независимых операторов, cooldown, гонки, отзыв и hold покрыты PostgreSQL. Офлайн-кворум Superadmin не проверялся. |
| Joining и Import | Chromium прошёл: адресное приглашение, запрет чужого tenant, заявка и одобрение, отдельные CSV и XLSX preview → confirm → claim → pending. Запрет перечисления аккаунтов и межорганизационные SQL-сценарии покрывает PostgreSQL. |
| Отказы | Chromium прошёл: Redis недоступен — новый вход закрыт, существующая сессия работает. API остановлен — запрос браузера не проходит, после запуска сессия снова доступна. |
| CSRF и прокси | Проверены запрос без CSRF, чужой Origin, браузерный вход с поддельным X-Forwarded-For, а также тесты Redis для доверенного peer, поддельного forwarded IP и проверки подмены на edge. Настройка внешнего доверенного прокси и публичного TLS не проверялась. |
| PostgreSQL SECURITY DEFINER | Реальные ограниченные роли: API не может вызвать issuer напрямую, worker не может вызвать import, а вызов API import без сессии отклоняется. TEN-01 проверяет RLS, подмену tenant и повторное использование соединения. Полная ревизия полномочий всех definer-функций остаётся отдельной задачей. |
| Секреты | Браузерные журналы содержат результаты и агрегаты тайминга. Письма, TOTP, cookies и proofs используются только во временном стенде, трассы и снимки не сохраняются. Gitleaks проверяет Git, а production smoke проверяет вывод конфигурации и контейнеры. |

При разработке тестов учтены штатный отказ 409 при наличии старой cookie и общий бюджет MFA между началом и завершением step-up. Для проверки следующего этапа тест сбрасывает только Redis из изолированного проекта после подтверждённого 429. Политики приложения не изменены.

## Замеры задержек

Windows Docker Desktop, loopback HTTPS Chromium. Замер от отправки POST до полного чтения ответа, без получения CSRF. Запросы чередовались, по четыре на каждую группу. Для bulk preview использованы разные fingerprint, чтобы не замерять только возврат готовой партии. Известный адрес bulk preview не имел локального членства.

| Маршрут | Известный адрес, медиана (мин–макс), мс | Неизвестный адрес, медиана (мин–макс), мс |
|---|---:|---:|
| Login, неверный пароль | 68,9 (58,1–76,5) | 67,8 (57,5–90,6) |
| Registration | 68,4 (54,8–81,9) | 77,6 (58,0–89,3) |
| Password reset request | 10,3 (7,3–12,4) | 9,1 (7,3–10,3) |
| Bulk preview | 15,2 (14,5–15,8) | 14,9 (13,3–16,2) |

Диапазоны пересекаются. В первом прогоне медиана регистрации для известного адреса была на 9,2 мс ниже. При повторе медианы для известного/неизвестного адреса составили 51,5/58,3 мс для входа, 50,5/51,9 мс для регистрации, 3,5/3,4 мс для reset и 12,6/12,4 мс для bulk preview. Выборка ограничена и не позволяет подтвердить отсутствие бокового канала. Сетевая среда, кэш, параллельная нагрузка и реальные профили требуют отдельного замера. Восемь конкурентных входов в стенде проверяют отклонение избыточной Argon2id работы с 503. Это проверка ограничения, без оценки эксплуатационной пропускной способности.

## Риски и условия активации

| Критичность | Область | Статус |
|---|---|---|
| Высокая | Внешний SMTP | Проверен только закрытый mailbox. Нужны отдельная проверка доставки, защиты конфигурации, повторов, отказов и уведомлений. |
| Высокая | Политика скомпрометированных паролей | Стенд использует локальный блоклист. Источник данных, обновление и сценарий недоступности ещё требуют проверки. |
| Высокая | MFA-ключи | Проверен отдельный тестовый keyring. Production-хранилище ключей, доступ, ротация и восстановление требуют эксплуатационного прогона. |
| Высокая | Независимое recovery | Ручная проверка личности и передача секрета требуют операционного регламента. Эксплуатация офлайн-кворума Superadmin и учение не выполнены. |
| Высокая | TLS, прокси и отключение маршрутов | Loopback TLS и выключенные маршруты в production Compose проверяются. Реальная цепочка TLS, доверенные прокси, политика forwarded headers и откат конфигурации требуют внешнего стенда. |
| Высокая | Резервное копирование и восстановление | Перезапуск PostgreSQL и upgrade с данными проверяются. Эксплуатационный restore, измерение RPO/RTO и сохранность ключей не подтверждены. |
| Средняя | Timing и нагрузка | Нужны расширенные замеры перечисления, Argon2id admission, Redis и глобальной advisory-блокировки. |
| Средняя | Мониторинг | Не проверены production-метрики и оповещения по Auth, rate limit, очереди почты, очистке staging и ошибкам recovery. |

При откате стенда отключаются тестовые overlays и перезапускаются API и worker без удаления данных. Существующие Nginx ограничения остаются для WebSocket, загрузок и долгих запросов. Exam Engine, Studio, Judge и Windows Agent не входят в эту проверку.
