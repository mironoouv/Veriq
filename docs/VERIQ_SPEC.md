# VERIQ_SPEC — функциональное ТЗ v1.0

## 0. Термины
- **Organization/Tenant** — независимая образовательная организация; вся бизнес-информация имеет tenant scope.
- **Account** — глобальная учётная запись, может состоять в нескольких организациях.
- **Membership** — членство пользователя в организации; роли относятся к членству.
- **Assessment** — шаблон работы (экзамен, контрольная, самостоятельная, практическая, тренировочная).
- **Publication** — неизменяемая опубликованная версия шаблона.
- **Assignment** — назначение публикации группе/студенту с окном доступности.
- **Attempt** — индивидуальная попытка студента с серверным таймером и снимком варианта.
- **Agent Device** — зарегистрированный Windows ПК, не личность студента.
- **Pairing** — временная связь конкретной попытки с разрешённым устройством.
- **Proctoring Session** — активная, явно обозначенная сессия мониторинга, не равна постоянному device heartbeat.

## 1. Состав v1.0
### Пользователи и организации
- Создание/управление организациями системным администратором; личные пространства и переключение текущей организации.
- Системные роли: Superadmin (платформенный), Org Admin, Teacher, Proctor, Student, Technician (tenant scoped). Несколько ролей и членств одновременно.
- Саморегистрация с подтверждением email; приглашения (одноразовые, срок, область, защита от перебора); групповые коды; заявки/модерация; импорт CSV/XLSX с preview, dry-run, идемпотентностью, сопоставлением колонок и безопасной обработкой дубликатов.
- Учебные группы, курсы/дисциплины, преподаватели, участники; архивирование, перенос между группами и управление доступом.

### Studio, Question Bank
- Личные банки, делегирование `view/use/edit` коллегам, банки организации; владелец управляет ACL, доступ между tenant запрещён.
- Типы заданий: single choice, multiple choice (частичные баллы по правилам), short text, essay, match/order, code, SQL, file upload.
- Разделы, категории, теги, версии, шаблоны, вложения/изображения, Markdown/математика (KaTeX), предпросмотр глазами студента, сортировка, клонирование.
- Draft → Published snapshot; изменения draft и банка не меняют активные попытки. Импорт Moodle XML/QTI — возможное расширение, не блокер v1.0.
- Параметризованные задачи и выбор из банка с контролируемым seed; обеспечивать одинаковую сложность по правилам преподавателя.
- **Все 8 параметров:** таймер; число попыток; рандомизация; автосохранение; Agent-required; политика показа ключей; ручная проверка; расписание/дедлайн.

### Schedule & Assignment
- Виды День/Неделя/Месяц, список задач, фильтр по группам/дисциплинам, события с местом/временем/организацией.
- Назначение одной публикации через календарное событие и/или через список работ без календарного события. Единая запись assignment; расписание — представление поверх данных, не дублирование экзамена.
- Времена хранятся в UTC; IANA TZ у организации/назначения; корректная обработка DST/локальных переходов и границ включения.
- Публикации, назначения и попытки — разные state machines. Уведомления о переносе/отмене, запланированное открытие по серверному времени.

### Exam Session
- Создание попытки только при подтверждённых правах и окне доступности, атомарном лимите попыток и обязательных preflight-проверках агента.
- Серверный таймер (`deadline_at`, `remaining_on_pause`); пауза/возобновление/продление через транзакции с versioning; автоматическое закрытие по дедлайну даже без активного websocket.
- Свободная навигация по заданиям; одно управляющее соединение/lease на попытку; безопасная передача управления и повторное связывание агента при смене ПК.
- Ответы сначала в локальной IndexedDB, затем идемпотентная отправка с sequence/revision и подтверждение из PostgreSQL; состояния UI `local / syncing / confirmed / conflict / late`.
- Strict connectivity: блокировка ввода при потере соединения, время продолжает идти; Limited-offline: локальный черновик на ограниченный интервал, сервер принимает только изменения, допустимые по серверной политике/дедлайну. Не доверять клиентским timestamp.
- Offline невозможно криптографически доказать, что ответ написан до дедлайна. Непроверенный черновик — pending_review или отклонение; преподаватель вправе продлить/разрешить по журналируемому исключению.
- Не считать потерю агента автоматически виновностью. При критическом сбое показывать явное состояние и разрешённые действия.
- Submit идемпотентен; повторная отправка не создаёт вторую проверку/оценку. При незавершённой ручной проверке результат preliminary.

### Grading
- Сумма max_points, earn_points, percentage; custom grade scales per organization; диапазоны без пересечений, границы чётко определены, шкала снимком при публикации.
- 5-балльная/процент/зачёт; частичные баллы и ручные rubrics. Judge даёт машинную оценку; teacher review, regrade с причиной и audit trail.
- Результаты: сразу, после конца окна, после проверки всех или вручную; ключи ответов и баллы — независимые политики видимости.

### Agent & Monitor
- Агент один раз устанавливается на общие Windows ПК, **без входа студента в агент**. Регистрация вручную или массово с одобрением. Профили Basic / Standard / Strict (последний лишь при управляемой конфигурации Windows).
- Device Service онлайн в режиме ожидания с минимальной технической телеметрией; Desktop capture только при активной разрешённой exam session, явная индикация; после сдачи стоп.
- Browser-to-agent pairing через один из проверенных вариантов loopback или `veriq://` fallback; short-lived signed/opaque one-time grants, backend validates, no raw student credentials transmitted.
- Централизованные группы ПК, конфигурации и команды; обновление по каналам, подписи и откаты; активные экзамены не прерывать плановым обновлением.
- Live-only screen viewing, несколько назначенных наблюдателей, миниатюры/полноэкранный просмотр, WebRTC SFU candidate; **никаких записей/скриншотов/архива**, никаких скрытых мониторингов вне экзамена.
- Инциденты: метаданные событий без содержимого экрана, кастомные реакции log/warn/notify/technical_pause, решение человек принимает по неоднозначным событиям.
- Срок хранения инцидентов per tenant + обязательный автоматический сборщик/удаление; отделить retention incident/audit/student results.

### Judge
- Изолированный код runner для Python/C++/C# (точный список компиляторов в версии 1 фиксируется по готовности runner), и отдельный SQL runner на временных базах.
- Асинхронная проверка по очереди с max concurrency, лимит CPU/RAM/pids/time/output, без сети, read-only FS + tmpfs, drop capabilities, non-root, seccomp/LSM, отдельный worker pool и хост; никакого Docker socket в доступе недоверенного решения.
- Для SQL выделенные ephemeral PostgreSQL, только минимальная роль и схема, отсутствие доступа к production DB; sql injection не mitigated фильтром ключевых слов — изоляция и privileges. Поддержка SELECT и при необходимости DDL/DML лишь в sandbox.
- Скрытые тесты, эталонные ответы и secrets не передавать в браузер; судейские результаты reproducible, max output, retry на системных ошибках без двойного начисления баллов.

### Admin / Storage
- Список устройств и сессий, политики, диагностика, мониторинг, отчёты и Audit Center.
- Резервные копии (полные + дифф./инкр.) и непрерывный WAL; отдельное хранилище; цель RPO ≤5 мин/RTO ≤1 час **измеряется** restore drills.
- Admin Storage view: диск/разделы/volumes, объём PostgreSQL/WAL/uploads/temp/backups, истории backup, last verified restore, предупреждения о 70/85/95% (порог configurable), dry-run очистки + step-up auth, невозможность удаления последней восстановимой цепочки, штатная retention expiry.

## 2. Критерии первого production релиза
- Данные двух организаций не доступны друг другу даже через подмену ID.
- Восстановление ответа, подтверждённого сервером, после закрытия браузера и рестарта API.
- Невозможно получить двойную попытку из гонки, продлить таймер изменением времени ПК, отправить баллы с клиента.
- 30 параллельных агентов и мониторинг класса измерены на целевом оборудовании и сети; метрики фиксированы.
- Code/SQL sandbox выдерживает злоумышленные случаи без исходящего доступа к production.
- Суперадминистратор/админ/техник не работают без MFA; безопасное восстановление.
- Backup restore drill реально демонстрирует RPO/RTO; dashboard не должен показывать «зелёный» статус без свежих доказательств.

## 3. Границы релиза
Не входят: ИИ-обвинения/автоматические санкции по косвенным признакам; постоянно работающая скрытая запись; видеозапись; кейлоггер; доступ к личным сообщениям; произвольные удалённые shell-команды; обучение/прокторинг через камеру и микрофон; гарантированная защита от любого списывания.
